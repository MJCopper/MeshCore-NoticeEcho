Transmission verification

NoticeEcho checks for local radio transmission activity and can also recognise your message being repeated by another node. These checks do not confirm delivery to recipients. Missing confirmation does not necessarily mean the message failed.

Optional retry

Off by default. Allows one extra send of a message part when neither local transmission activity nor a matching heard repeat verifies the first attempt. The message may already have arrived, so retrying can produce a duplicate. Local transmission evidence is enough to prevent this retry, even if no repeat is heard. Remaining parts continue when verification is unavailable.

This option controls retries of uncertain transmissions. Recovery from connection failures and certain rejected sends is handled separately.

Additional evidence

On by default. Recognises another node repeating the exact message packet. A repeat provides stronger evidence than local radio activity, but is not required for verification and does not prove delivery to intended recipients.

Advanced verification settings
Verification timing

Default: 5 seconds per message part, starting after the send command returns. Stops early when local transmission activity or a matching repeat is detected. Command preparation and response time are additional. Applies even when heard-repeat evidence is off.

Default: 5 seconds after the initial verification wait. Applies only when the optional retry is on. Local transmission evidence or a matching repeat arriving during this wait cancels the retry.

Default: 60 seconds. Applies only when heard-repeat evidence is on. Continues observing after initial verification to update history; it does not hold the queue for this duration. Tracking may be extended to cover a pending retry, which a matching repeat can cancel.

Local verification uses the companion’s overall transmitted-packet counter. It indicates radio activity rather than an acknowledgement for this exact message; heard repeats are matched to the exact packet.

Saved settings apply to newly queued notices. Each queued notice keeps its saved verification policy.
